# V27: display domains off while the screen is dark

`display-v27.patch` is a complete patch against the pinned base in
`kernel-base.txt`, as v26's is. It differs from v26 only in the display driver
(`drivers/gpu/drm/sysfb/`): `pixel_scanout.c` changes and three headers are
new.

- `pixel_power.h`: the DPU/DISP power cycle and pipeline rebuild that
  `kernel/display-cycle`'s test module proved. Down: DSIM into ULPS, the
  DSIM PHY isolated, then DPU and DISP off with stock's genpd sequence. Up:
  the reverse, then `dsim_reg_init()`'s order with the registers read before
  power-off, and every DECON, window, DSC, DMA and DPP configuration
  register written back.
- `pixel_disp_regs.h`: the registers it reads and restores, generated by
  `kernel/display-cycle/gen-disp-regs.py`.
- `pixel_display_pd.h`: the DPU and DISP save lists, copied from
  `kernel/pd/pixel-pd-lists.h`.

**What the driver does**
- With the panel asleep at screen-off (`panel_sleep`), `pixel_scanout`
  powers the domains off. It holds the frame IRQs off until they come back.
- At screen-on it powers them back on and rebuilds the pipeline, then wakes
  the panel as before.
- `pixel_scanout.display_power` (default Y, writable) turns this off.
- Debugfs `pixel_scanout` shows `display_powered_off` and
  `display_power_cycles`.
- Shutdown leaves the pipeline as it is. The bootloader brings the display
  up from either state; a restart with the domains off was checked.

**The boot script.** With this kernel, `pixel-persistent-session.sh` gives
`pixel-pmic-opmode` the whole stock sleep set (`suspend=all`), adding the
camera, INT and MIPI/UFS PLL rails. It also loads `pixel-sleep` with
`display_off_required=1`, which refuses a sleep while a display domain is
powered: with those rails off, a powered display domain does not wake.

**Validated by RAM boot on October 1, cable in, charger input off**
- Five screen off/on cycles and about fifteen more through the suspend
  adapter. Each time both domains read off while dark, and frames completed
  after the next screen-on with no failures or DSI underruns.
- The user confirmed the picture looked normal after the cycles.
- Deep-sleep current, measured within the same boot:
  - display power-off on against off: 82.5 and 83.6 mA against 84.7 and
    85.0 mA, about 1.8 mA less;
  - adding the stock sleep rails: 84.0 to 78.2 mA, about 5.8 mA less.
- RAM boots read 10–30 mA higher than the installed image under the same
  conditions, so only differences within one boot count.

Built with `scripts/build-pixel-shell.py --persistent-root --seconds 0 --cma
256M`, as v26. `kernel.config` matches v26's except for the initramfs path.

**Installed in boot_a on October 1** with the user's approval, through
`scripts/install-pixel-boot.py` from a RAM boot of the same image (direct
readback matched `a92d0e7e…`; the previous image was `deepsleep-image-2`,
`bfa256d8…`). Reboot validation:
- the build ID matched;
- `display_power` and `display_off_required` were on, with `suspend=all`;
- frames completed;
- a deep sleep with the screen off woke on the alarm, and the screen came
  back;
- the boot held past four minutes.
