# Idle power — September 28, 2026

Image X (kernel [v23](../kernel/power-v23/README.md)) cuts the phone's draw
by a third with the screen on and by 43 % with it off. It is in `boot_a`.

| Whole phone, from USB | Image W (morning) | Image X |
|---|---|---|
| Screen on, idle, 120 Hz | 3.01 W | 2.09 W |
| Screen off | 2.87 W | 1.65 W |

## Method

**USB input.** `scripts/pixel-usb-power.py` runs on the phone and samples
VBUS × USB input current four times a second:
- VBUS from the TCPC's VBUS_VOLTAGE register (25 mV per LSB);
- the input current from the MAX77759 gauge's IIn (about 0.125 mA per LSB).

For a measurement the charge limit is set below the current percentage. The
charger then runs buck-only, the battery rests (about −3 mA), and USB
carries the whole phone. The figures include charger conversion losses.
Single 20 s runs vary by about ±0.1 W, so comparisons were repeated or
alternated.

**Per rail.** The [ODPM module](../kernel/odpm/README.md) reads 24 rails from
the two PMICs' power meters. That is how the panel's 87 mW with the screen
off, the idle memory rails and the dead radios were found.

## What changed, largest first

1. **CPU idle spun on rejected C2 entries** (−0.65 W with the screen off).
   Every idle CPU asked the firmware to power down, was refused, and asked
   again. The [cpupm module](../kernel/cpupm/README.md) supplies the PMU
   hints the firmware needs and the timer broadcast a powered-down core
   needs.
2. **Unused power domains** (−0.2 W). The bootloader leaves the camera
   pipeline, TPU, codecs, G2D, EH and AUR on; the
   [pd module](../kernel/pd/README.md) turns them off.
3. **MIF with the screen off** (−0.15 W, A/B-tested). The display now
   releases the memory clock to 421 MHz while the panel is off.
4. **The thermal poll** runs at 100 ms below 60 C instead of 20 ms, so it no
   longer wakes an idle CPU 50 times a second.

## Where the rest goes

Screen off, image X, one ODPM reading (mW):

| Rails | mW |
|---|---|
| INT + INT_M | 135 |
| LLDO/MLDO feeds (I/O, PLL, UFS, USB supplies) | 260 |
| CPU clusters (C2 per core, clusters stay up) | 120 |
| SA + SD | 100 |
| Panel (display off, not asleep) | 87–97 |
| Camera and GPU rails, domains off | 95 |
| MIF + DRAM + SLC | 60 |
| Modem, mmWave, RF front end, WLAN/BT | 0 |

The rails sum to about 0.9 W of the 1.65–1.8 W input. The rest is charger and
buck losses and loads the meters do not cover.

The next steps, in rough order of reward:
- **System suspend while the screen is off.** Stock Android spends screen-off
  time suspended.
- **Cluster power-down.**
- **The camera and GPU buck voltages.** Changing the GPU clock while its
  domain is gated has reset the phone before.
- **Panel sleep.** It needs the panel's full init sequence to restore DSC.
