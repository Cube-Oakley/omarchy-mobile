# Modem-aware suspend bring-up

The Pixel shell can now enter guarded s2idle after screen-off while unplugged.
Calls, audio and the charger inhibit it. This is an initial suspend integration;
measured power savings remain modest and deeper GS201 power modes are unfinished.

## Prerequisites repaired

- UI accelerometer subscriptions use USF's non-wakeup channel. The old 15 Hz
  stream renewed a 200 ms wake lock continuously, preventing task freezing.
- CPIF patch 0009 propagates the modem's suspend refusal. An asserted CP wake
  line now aborts suspend instead of being ignored.
- The modem's root port and endpoint use a private PM domain. CPIF retains
  ownership of PCIe power and saved configuration through suspend/resume;
  generic PCI PM no longer retrains an isolated controller before CPIF wakes it.
- The persistent modem bundle loads `pixel-wdt-pm` after starting its watchdog
  feeder. It pauses/rearms the AP watchdogs during the noirq/sleep interval.
  An actual 44.8-second RTC sleep resumed with the same boot ID and original
  watchdog control/reload values, exceeding the normal watchdog timeout.

## Modem reporting

The application service owns the only SIT IPC0 connection. Its `screen-state`
action takes a strict boolean and refuses screen-off during a live call.
It sends the stock screen-state request (0902, uint32), followed by the stock
optional indication filter (0928, uint32). The foreground mask is ALL
(0xffffffff); the sleeping mask is NONE (0). A partial failure invalidates
the cache so foreground restoration sends both requests again.

The payload layouts are from the phone's stock
`ProtocolDeviceInfoBuilder::SetScreenState` and
`ProtocolMiscBuilder::BuildSetUnsolicitedResponseFilter`. The latter passes the
[AOSP IndicationFilter](https://android.googlesource.com/platform/hardware/interfaces/+/refs/heads/main/radio/1.2/types.hal)
mask unchanged: optional signal strength, minor network changes, dormancy,
link capacity and physical-channel reports. It does not filter calls, SMS or
significant registration/data changes.

Screen-state alone still delivered eight signal-strength reports in ten
seconds. With the optional-report filter, a ten-second check delivered none.
`power-status` exposes counts keyed by indication ID, without message payloads
or subscriber identifiers.

## Measurements so far

With the screen dark, LTE/IMS registered and Wi-Fi connected:

| Measurement | Result |
| --- | --- |
| Awake, whole-phone USB input, charging paused | 1.55 W mean over 20 s |
| Awake, ODPM metered rails | 0.938–0.949 W |
| Three filtered-report s2idle intervals | 12.630 s, 37.276 s, 1.035 s |
| ODPM averages spanning those intervals and transitions | 0.846 W, 0.812 W, 0.814 W |

All three ended on CP2AP_WAKEUP (IRQ51), without a SIT indication in the
two-second observation window after wake. The modem can also wake for data
or its other IPC channels. These are not proof of call/SMS-triggered wake.

ODPM meters only part of the phone. Its totals cannot be substituted for USB
input or used to claim a whole-phone battery improvement. The remaining idle
rails and firmware-managed SoC clock/power modes still need investigation;
ordinary s2idle is not the stock GS201 platform's deep sleep sequence.

An initial user call worked after resume, but its probe had already woken after
0.286 seconds before the call arrived. It validates post-resume calling only.
A second early call test also worked after resume; its probe first slept 30.586 seconds,
then subsequent sleep attempts were refused before the incoming indication.
Tracing those later refusals identified Wi-Fi, not CPIF: brcmfmac timed out
waiting for D3 acknowledgement (`0000:01:00.0`, suspend, error -5). Its in-band
idle state showed `active host-active 1` with zero device-wake timeouts.
A temporary Wi-Fi driver reload with `deep_sleep=0` isolated the issue; that
option was restored afterward and was never installed persistently. The
[incremental Wi-Fi patch](../kernel/suspend/README.md) defers D3 completion
until the control-ring read pointer is committed. With normal Wi-Fi idle
power saving restored, eight consecutive RTC sleeps (7.1–8.2 seconds actual
each) passed, with Wi-Fi HTTPS working after every wake and zero device-wake
timeouts. The patched module is now pinned in the persistent modem bundle;
normal reboot loaded the matching module build ID, started the modem without
manual intervention, and passed an 8.643-second RTC sleep with cellular HTTPS
working afterward.

With Wi-Fi in-band idle temporarily disabled, one incoming IMS SMS woke the
AP after 26.839 seconds of actual sleep: IRQ51 and indication 0d1e. The
service acknowledged and imported it, the Messages app consumed it, and the
user confirmed it was visible. The screen remained dark, as intended for
background SMS handling. With the Wi-Fi fix loaded and normal idle power saving active, a subsequent
incoming call woke the AP after 57.612 seconds of actual sleep: IRQ51 and
indication 0d01. The user confirmed answering, two-way audio and ending the call.

## Guarded diagnostic helper

`scripts/pixel-suspend.py` is installed as `/usr/local/sbin/pixel-suspend`.
The shell adapter delegates to it and the existing sleep policy is enabled
on the test phone. An unplugged screen-off test recorded five automatic sleeps:
2.793, 8.648, 30.783 and 0.787 seconds ending on modem wake, followed by 73.876
seconds ending on the power key (116.887 seconds asleep in total). The user
confirmed the touchscreen worked after waking. USB did not re-enumerate after
replugging with the screen on; a normal restart restored it, allowing recovery
of the persistent sleep log. USB recovery after unplugged suspend remains an
open issue at that checkpoint. The previous modem shutdown was clean.
The September 30 investigation subsequently identified the MAX77759 USB2
data switch opening on cable removal; see the [recovery fix](../kernel/usb/README.md).

The helper requires the persistent supervisor, online/registered
modem, no live call/audio, watchdog PM module, RTC and power-key wake, and
selected s2idle. It refuses a charger unless `--allow-charging` is explicitly
used. A 10–3600 second RTC fallback bounds each sleep; the default is 15 minutes.
The Pixel currently retains that fallback even with background checks set to
Never, pending longer unattended validation.

It applies screen-off reporting, bounds the blocking wakeup-count read to
three seconds, rechecks call state, and uses the kernel wakeup-count handshake
to avoid sleeping over a pending event. It preserves an earlier RTC alarm or
restores a later one, without replacing a newly scheduled alarm on cleanup.
Cleanup attempts modem foreground reporting and display restoration even if
alarm restoration fails. `--keep-dark` leaves display control to the caller.

USB disconnects during suspend. The host's manual USB network configuration
can disappear on reconnect; use `pixel-reboot.py`'s `network_up()` before
interpreting SSH failure as a phone hang. Normal reboot can likewise need a
second network setup after the final gadget enumeration.

## Remaining platform power work

The stock `exynos-cpupm` has a system clock-down mode (SICD) beyond the C2/CPD
hints currently supplied by `kernel/cpupm`. It requires all siblings idle,
idle-device checks, drained ACPM IPC, SICD enter/exit notifications and PMU
wake masks. The stock GS201 sequence saves four AUR clock registers when
that domain is powered; its enter sequence itself is empty, and the firmware
selects SICD through CPU_INFORM=3. Exit/early-wake clear the corresponding
wake enables and PMU interrupt pending bits.

This is not safe to reduce to setting a CPU hint. The custom GPIO, keys and
RTC drivers currently enable their GIC wake IRQs; they do not assemble the
stock PMU EINT wake masks. SICD needs matching PMU routing for modem, power key
and RTC before a bounded live trial. The current PMU/CPU helpers implement
C2/CPD, not that complete system sequence. No SICD or deep-sleep register
experiments have been performed in this session.
