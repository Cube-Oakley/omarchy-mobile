# Installing packages and upgrading the Pixel safely (2026-10-01)

The phone runs a persistent Arch Linux ARM root (ext4 on `userdata`). It boots
our own kernel from boot_a, so no Arch kernel package is involved. This note
covers how packages get on the phone and what can break. `scripts/pixel-update.py`
enforces the rules.

## What is there today (read on the phone)

- **Packages.** 383 installed, 51 explicitly; none foreign. The last full
  upgrade was on September 25.
- **No package server of its own.** `/etc/pacman.d/mirrorlist` is
  `http://127.0.0.1:8000/$arch/$repo`. That is the temporary tunnel used for
  the first install: the host ran `scripts/arch-usb-mirror.py` (a USB-only
  cache of the official mirror) and a reverse SSH tunnel carried it.
  - Without the tunnel, pacman cannot download anything.
  - The phone now has Wi-Fi, so the official
    `http://mirror.archlinuxarm.org/$arch/$repo` works directly. Signatures
    are checked either way (`SigLevel = Required DatabaseOptional`), and the
    Arch Linux ARM keyring is populated.
- **Custom builds pacman does not own.** These are what an upgrade can break:
  - **`/opt/pixel-mesa`: the GPU for the whole session.** Hyprland and the
    shell run with `LD_LIBRARY_PATH=/opt/pixel-mesa/lib` and its EGL vendor
    file. It is Arch's Mesa 26.2.3 plus one patch adding the Mali-G710 model
    entry (`adapter/userspace/mesa/0001-panfrost-add-g710-model.patch`);
    without it Mesa falls back to llvmpipe. It links `libdrm`, `expat`, `zlib`,
    `zstd` and an unversioned `libSPIRV-Tools.so`. A `spirv-tools` change can
    break it silently.
  - **libcamera 0.7.2 in `/usr/local/lib`,** with its own `libyaml`, built
    from `/root/build/libcamera-v0.7.2` with our patches. It links `gnutls`,
    `libudev`, and EGL/GLES through `libglvnd`.
  - **Omarchy Camera's QML plugin,** built against Qt 6.11.2 in
    `/root/src-camera`.
  - **Our kernel modules, scripts and firmware** in `/usr/local/lib/omarchy-mobile`
    and `/usr/lib/firmware/omarchy-mobile`. pacman never touches them.
- **Versions the mobile session depends on:**
  - Hyprland 0.56.2: the mobile config uses its Lua API (`hl.dispatch`);
  - quickshell 0.3.1: the shell's QML.

## Rules

1. **Full upgrades only.** `pacman -Sy` followed by installing one package
   leaves everything else on the old versions against a new database (a
   partial upgrade). That is the usual way an Arch system breaks. So
   `pixel-update install PKG` first upgrades everything, then installs.
2. **Hyprland and quickshell are held** (`--ignore`). They are upgraded on
   purpose, after checking the mobile config and the shell against the new
   version.
   - If one of Hyprland's libraries (aquamarine, hyprutils, hyprlang,
     hyprgraphics, hyprcursor, hyprtoolkit) moves to a new ABI meanwhile,
     pacman refuses the whole transaction and nothing changes. That is the
     signal to do the deliberate upgrade.
3. **Wi-Fi or the USB link only.** Never over mobile data (2 GB a month)
   unless asked.
4. **Snapshot before, check after, roll back if needed.** Each run writes
   `/var/lib/omarchy-mobile/updates/<time>/`:
   - the package list;
   - `/etc`;
   - tarballs of `/opt/pixel-mesa`, `/usr/local/lib` and the camera plugin;
   - `rollback.sh`, which reinstalls each changed package's previous version
     from pacman's cache (never cleaned by the tool) and restores the
     tarballs.

   After the upgrade:
   - every custom build and Hyprland/quickshell are scanned with `ldd` for
     missing libraries;
   - `/root/pixel-gpu-render-test` must still render in hardware.
5. **Watched packages say what to do:**

   | Package | Follow-up |
   |---|---|
   | qt6-base, qt6-declarative | rebuild the camera plugin |
   | spirv-tools, libdrm, expat, zstd, libglvnd, wayland | check or rebuild `/opt/pixel-mesa` |
   | mesa | keep `/opt/pixel-mesa` in step with it |
   | gnutls, systemd-libs | check libcamera |
   | pipewire, wireplumber | check audio |
   | networkmanager | check Wi-Fi and the USB profile |
   | python | check the helpers and the modem service |
   | glibc | reboot |

## The tool

```
pixel-update [--server URL] plan       # what a full upgrade would change; read only
pixel-update [--server URL] run --yes  # snapshot, pacman -Syu (pinned held), checks
pixel-update [--server URL] install --yes PKG...
pixel-update check                     # the post-upgrade checks alone
```

`plan` syncs a throwaway copy of the package databases (the `checkupdates`
method), so it never changes the system.

First run on October 1, against the official mirror over Wi-Fi:
- **15 upgrades pending.** ca-certificates-mozilla, cairo, coreutils,
  fastfetch, fribidi, hyprland-guiutils, hyprtoolkit 0.5.4 → 0.6.0, libpng,
  librsvg, libwireplumber, openssl, pam, pcre2, tzdata, and wireplumber 0.5.17
  → 0.5.18 (watched).
- **`check`:** no missing libraries, and the GPU renders in hardware (0.7 s).

## First real upgrade and install (October 1, 20:20, the user's go-ahead)

`pixel-update --server http://mirror.archlinuxarm.org/$arch/$repo --yes
install gst-plugins-base gst-plugins-good gst-plugins-ugly
gst-plugin-pipewire`, over Wi-Fi.

What it did:
- Wrote the snapshot and rollback script to
  `/var/lib/omarchy-mobile/updates/20261001-201959/`.
- Upgraded the 15 pending packages, with Hyprland and quickshell held. Hyprland
  does not link hyprtoolkit: only hyprland-guiutils, its dialog helpers, does,
  and that upgraded with it.
- Installed the 35 packages for video recording.

Checks:
- **Libraries and GPU:** no missing libraries; the GPU renders in hardware.
- **Hooks:** systemd's own post-transaction hooks say "Skipped: Running in
  chroot", as always on this root. The GIO and GSettings hooks ran.
- **Audio:** WirePlumber 0.5.18 was restarted by hand, the way the session
  starts it. Speakers and microphones are both there, and its mixer warnings
  are the same as the 0.5.17 start at boot. A tone played on the speaker was
  recorded by the microphone at −42 dBFS, against −60 for the quiet room.
- **Video:** Omarchy Camera recorded 1080p H.264 with Opus sound into MP4 at
  29 fps on the system's plugins.

The tool is installed as `/usr/local/sbin/pixel-update`. While pacman runs it
keeps a file in the shell's sleep-inhibit directory, so the phone cannot sleep
in the middle of a transaction.

## Not done yet, for the user to decide

- **The mirror list.** Point `/etc/pacman.d/mirrorlist` at the official mirror
  (keeping the tunnel as a commented alternative). Until then, pass
  `--server`.
- **A shell entry** (Settings > Updates) that shows `plan` and runs `run`.
- **Later:**
  - pacman hooks that run `check` after any transaction touching a watched
    package;
  - packaging `/opt/pixel-mesa` and libcamera as our own pacman packages
    (PKGBUILDs in a small repository), so pacman tracks them;
  - checking whether a newer upstream Mesa has the G710 entry, which would
    retire the custom Mesa;
  - a snapshot-capable root (btrfs) for whole-system rollback.
